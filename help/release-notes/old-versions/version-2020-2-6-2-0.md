# Version 2020.2 (6.2.0)

**Substance Painter 2020.2.0 (6.2.0)** introduit le nouveau workflow de Tuile UV qui permet la peinture entre les UDIM. Il inclut également plusieurs améliorations des performances et de la taille du projet pour tout type de projet.

Date de publication : *23 juillet 2020*

&#x200B;>> 

Crédits d&#39;artiste : Dragon de [Damien Guimoneau](https://www.artstation.com/damz) et Robot de [Jason Huang](https://www.artstation.com/jasonhuang).

## Principales fonctionnalités

### Nouveau workflow de Tuile UV avec la peinture entre UDIM

![](../../assets/banner-uvtiles.jpg)

Dans cette version, nous présentons le nouveau workflow de Tuiles UV à Substance Painter qui permet la peinture au-delà des Tuiles UDIM.

Avec le nouveau workflow, les **UV ne sont plus divisés en Jeux de textures individuels**. En revanche, les Tuiles UV sont contenues dans un seul Jeu de textures en fonction de l’affectation de matériau du maillage. Les tuiles UV qui se trouvent dans le même Jeu de textures peuvent être **peintes sans seams**, dans les viewports 2D et 3D.

Tuile UV est le terme utilisé pour décrire de manière générique ce nouveau workflow, car UDIM est principalement une convention de nommage. Bien qu&#39;UDIM soit actuellement la seule convention disponible, nous avons des projets pour l&#39;étendre à l&#39;avenir (comme la prise en charge du nommage Mudbox ou ZBrush). Nous envisageons également de prendre en charge les carreaux avec des coordonnées négatives, ce qui n’est pas possible avec le schéma UDIM. C’est pourquoi nous avons choisi un terme plus large pour ce workflow.

Voici un aperçu des modifications introduites avec ce nouveau workflow :

* **Création d&#39;un projet de Tuile UV**\
  Lors de la création d’un projet, un nouveau paramètre permet de spécifier si le nouveau workflow doit être utilisé ou non.

  Notez qu’une fois le workflow décidé et le projet créé, il ne peut plus être modifié par la suite, contrairement à d’autres paramètres.

  ![](../../assets/new-project-setting.png)
* Tuiles UV dans le Viewport 2D

  Lors de l’utilisation du flux de travaux de nouvelle Tuile UV, la Vue 2D affiche désormais une nouvelle grille avec un numéro d’UDIM dédié à chaque Tuile UV. Chaque carreau peut être peint individuellement.

  ![](../../assets/paint-2d-view.jpg)
* Peindre au-delà des Tuiles UV

  Tuiles UV

  qui se trouvent dans le même Jeu de textures peuvent être peints de manière transparente. Cela permet d&#39;augmenter la résolution générale et la qualité d&#39;un actif en multipliant simplement le nombre de Tuiles UV.
* Tuiles UV dans la fenêtre Liste de Jeux de textures

  Le

  La liste de jeux de textures a

  a été mis à jour pour répertorier les UV liés au matériau trouvé sur le maillage importé. Chaque Tuile UV s’affiche avec son nom en fonction de la convention de l’UDIM.

  ![](../../assets/uv-tiles-texture-set-list.png)
* Modification de la résolution par Tuile UV

  Bien que la résolution par défaut de chaque Tuile UV soit fonction de son Jeu de textures parent, il est possible de la remplacer par mosaïque. Sélectionnez simplement les vignettes dans la Liste des Jeux de textures, puis accédez à la fenêtre Paramètres de Jeu de textures pour modifier la résolution. Lorsque la résolution d’une mosaïque est remplacée, la nouvelle résolution s’affiche dans la vue 2D à côté de son numéro.

  ![](../../assets/override-resolution-uv-tiles.gif)
* Nouvelles icônes de pile de calques

  La pile de calques propose de nouvelles icônes pour la peinture et les calques de remplissage. Comme les Tuiles UV comportent beaucoup plus de textures, il n&#39;a pas été possible de toutes les afficher dans cette petite zone. Cela améliore les performances, car il n’est plus nécessaire de calculer des vignettes spécifiques. Ce nouvel ensemble d’icônes peut également être utilisé pour des projets standard en activant un paramètre dans les paramètres principaux (voir ci-dessous).

  ![](../../assets/layer-stack-icons.png)
* Nouveau masque de Tuile UV sur les calques

  Le masque de Tuile UV est une nouvelle façon de masquer les calques d’entrée/sortie qui est plus efficace que le masquage normal. Il offre de meilleures performances car il permet de se débarrasser complètement du calcul de Tuiles UV spécifiques. Il s’agit d’un outil que nous vous recommandons d’utiliser pour vivre une expérience confortable lorsque vous travaillez dans un projet avec de nombreuses Tuiles UV. Pour plus d&#39;informations, consultez la [page dédiée](../../interface/layer-stack/geometry-mask.md) dans la documentation.

  ![](../../assets/uv-tile-mask-3d-edition.gif){width="550px"}
* **Peindre à travers des Tuiles UV masquées**\
  Lorsque plusieurs Tuiles UV se trouvent dans le même Jeu de textures, il peut s&#39;avérer difficile de mettre en peinture certaines zones d&#39;un maillage en raison d&#39;autres parties de la géométrie gênantes. Pour éviter cette situation, un nouveau paramètre de peinture a été ajouté dans la barre d’outils contextuelle nommé **Les tracés de Peinture ignorent les Tuiles UV masquées**. Lorsque ce paramètre est activé, toute Tuile UV exclue via le masque de Tuile UV est masquée dans le viewport, ce qui permet aux contours de peinture de les passer ou de les ignorer. La modification du masque de Tuile UV recalcule les traits de pinceau, car elle permet de réimporter un maillage dont la Tuile UV modifiée ou la nouvelle géométrie doivent également être exclues. Cela évite de refaire les tracés de peinture.

  ![](../../assets/paint-through-tooltip.png)

  ![](../../assets/paint-through.gif)
* Tuiles UV de Baking

  Les bakers prennent également en charge les Tuiles UV et une liste de sélection apparaît désormais dans la fenêtre de baking

  pour spécifier les mosaïques et les Jeux de textures à baker. La sélection peut être rapidement modifiée en cliquant sur la case à cocher et en la faisant glisser, ou en utilisant les nouveaux menus déroulants.

  ![](../../assets/baking-window-uv-tiles.png)

  ![](../../assets/baking-menu.png)
* Exportation de textures de Tuiles UV avec la nouvelle balise $udim

  Une nouvelle balise a été ajoutée aux modèles de sortie qui permet d’exporter des fichiers avec le numéro de Tuile UV dans leurs noms de fichiers. Actuellement, seule la convention UDIM est disponible. Il est également possible d’utiliser des parenthèses pour définir des éléments facultatifs dans un nom de fichier lorsqu’une balise n’est pas disponible. Cela permet, par exemple, de créer des noms de fichiers qui ajoutent uniquement le numéro UDIM lorsqu’ils sont disponibles avec des projets de Tuile UV, ce qui rend les paramètres prédéfinis d’exportation compatibles avec tout type de projet.

  ![](../../assets/udim-tag.png)
* **Importation de séquences d&#39;images** Une séquence d&#39;images est une série de textures dont chacune correspond à une Tuile UV spécifique. Pour importer une séquence d’images, il vous suffit de glisser-déposer le premier fichier de la séquence dans l’Étagère ou d’utiliser la fenêtre des ressources d’importation. Les fichiers restants dans la séquence seront également importés automatiquement. Les séquences s’affichent dans l’Étagère sous la forme d’une ressource unique avec un numéro indiquant le nombre de fichiers qu’elles contiennent. Pour utiliser la séquence, il vous suffit de la faire glisser et de la déposer dans un calque de remplissage. Le mode projection sera automatiquement défini sur **Remplir (correspondance par Tuile UV)**.

  ![](../../assets/image-sequence-shelf.jpg){width="600px"}

  ![](../../assets/fill-projection-mode-uv-tiles.png)
* Prise en charge des facesets avec des maillages alembic

  Les facettes alambiques sont désormais importées en tant que matériaux pour être divisées en Jeux de textures. Cette modification rend les maillages Alembic compatibles avec le nouveau workflow de Tuiles UV. Si un maillage Alembic contient des faces qui ne se trouvent pas dans un jeu de faces, elles sont automatiquement placées dans un Jeu de textures nommé DefaultMaterial.

Pour en savoir plus sur le nouveau workflow de Tuile UV, consultez la [documentation dédiée](../../features/uv-tiles/uv-tiles.md).

>
> Le workflow de Tuile UV peut être très exigeant. Nous vous recommandons de travailler avec des SSD pour stocker à la fois le cache et un fichier de projet afin de réduire les temps de chargement et d’obtenir une expérience fluide.

### Nouveau Moteur de pause

![](../../assets/banner-pause-engine.jpg)

Il est désormais possible de suspendre le moteur de la Substance Painter pendant le travail. Le moteur étant suspendu, tout calcul de texture, mise à jour de viewport ou contour de peinture est enregistré mais non calculé.

Cette nouvelle action permet de configurer et de modifier des piles de calques complexes et de retarder le calcul jusqu’au dernier moment. Le principal avantage de mettre le moteur en pause est d&#39;éviter les calculs intermédiaires et de ne calculer que le résultat final. Cela rend l’application plus réactive et la mise à jour globale plus rapide. Le compromis est qu&#39;il n&#39;y a pas de retour visuel tant que le moteur n&#39;est pas en pause.

Pour suspendre le moteur, cliquez simplement sur le bouton **dans la barre d&#39;outils contextuelle** au-dessus du viewport, ou utilisez **Maj raccourci + Échap** (peut être modifié dans les Paramètres). Pour reprendre le moteur, désactivez le bouton ou réutilisez le raccourci.

![](../../assets/pause-animation.gif)

### Améliorations des performances

![](../../assets/banner-performances.jpg)

* **Exportation plus rapide des textures**\
  L&#39;exportation des textures devrait être beaucoup plus rapide, en particulier avec les projets lourds qui génèrent de nombreuses textures. Plusieurs améliorations ont été apportées à la génération et à l’écriture des textures. Lors de nos tests internes sur des projets comportant de nombreux jeux de Textures ou des piles de calques complexes, nous avons constaté que le processus d&#39;exportation était généralement jusqu&#39;à **4 ou 5 fois plus rapide**.
* **calcul de la mémoire cache retardé lors de l’ouverture des projets** La Substance Painter utilise un système de mémoire cache pour permettre des ajustements et des fusions rapides de calques. Dans les versions précédentes, ce cache était calculé à chaque ouverture d’un projet (visible par la barre de chargement verte en bas du viewport). Désormais, le calcul de cache n’est déclenché que lors de la tentative de modification d’un calque (en peignant ou en modifiant un paramètre de calque de remplissage, par exemple). Cette modification permet d’ouvrir des projets sans attendre et sans passer aux Jeux de textures souhaités avant de commencer à travailler. Le calcul est également plus granulaire, ce qui permet de ne calculer que ce qui est nécessaire. Par exemple, dans un projet contenant des Tuiles UV, seules les vignettes devant être modifiées sont calculées.
* **Le chargement asynchrone des maps de maillage** Les Maps de maillage sont désormais chargées de manière asynchrone. Cela signifie que l’application ne sera plus bloquée en attendant le chargement des maps de maillage. Ceci est particulièrement visible lors de l’affichage de la map de maillage dans le viewport (comme dans l’image ci-dessous). Cela permet également d&#39;ouvrir les projets plus rapidement puisqu&#39;il n&#39;y a plus d&#39;attente pour les maps de maillage.

  ![](../../assets/meshmaps-loading.gif)
* **Modification améliorée du mode d&#39;affichage du masque**\
  Lorsque vous cliquez sur un masque tout en maintenant la touche ALT enfoncée (ou sur le mode d’affichage dédié) pour l’afficher dans le viewport, les mises à jour de texture ne sont désormais effectuées que pour le masque. Cela signifie que la peinture et la modification des effets sont beaucoup plus fluides avec ce mode d&#39;affichage, car tous les autres calculs sont retardés jusqu&#39;à ce que le viewport soit repositionné dans le mode de matériau.

  ![](../../assets/mask-view-mode.png)
* **Vignettes de nouvelles piles de calques**\
  Comme mentionné précédemment, la pile de calques peut désormais utiliser un nouvel ensemble d’icônes. L’utilisation de ces icônes peut améliorer les performances générales car aucune vignette n’a besoin d’être calculée. Bien que cela soit automatique pour les projets de Tuile UV, les projets réguliers peuvent également choisir d&#39;utiliser ces icônes en accédant à **Modifier > Paramètres** et en activant **Remplacer les vignettes de pile de calques par des icônes**.

  ![](../../assets/icon-setting.png)
* **Enregistrement incrémentiel plus rapide** Comme le projet peut être plus petit et que le processus d’enregistrement est plus granulaire en ce qui concerne les données qui ont été modifiées, l’enregistrement incrémentiel (en appuyant sur CTRL+S) est désormais beaucoup plus rapide. Ceci est particulièrement visible sur les projets lourds.
* **Performances de démarrage d’Iray améliorées**\
  Le passage au mode de rendu avec Iray devrait être plus rapide car nous avons amélioré la façon dont nous gérons la mémoire partagée au sein de l’application.

### Améliorations de la taille du projet

![](../../assets/banner-filefootprint.png)

Les fichiers de projet sont connus pour avoir une [empreinte de fichier importante](../../technical-support/workflow-issues/project-issues/projects-are-really-big.md). Nous avons pris le temps d&#39;étudier la cause profonde de ce problème et avons conçu quelques solutions. Cette version introduit un premier ensemble de modifications :

* **Permutation des sorties baker en images en niveaux de gris**\
  Dans les versions précédentes, les bakers produisaient des images de RGB dans tous les cas. Désormais, les bakers en niveaux de gris (courbure, ambient occlusion) génèrent uniquement des images en niveaux de gris. Cette simple modification peut réduire la taille des projets de 20 % à 60 %. Pour tirer parti de ce changement, les maps de maillage des projets existants doivent être régénérées.
* **Modification des paramètres de diffusion et de dilatation par défaut pour les bakers**\
  Auparavant, les bakers généraient une dilatation de 1 pixel, puis un motif de diffusion (pixels flous en dehors des Îlots UV). Cette configuration génère des textures assez lourdes car les dégradés sont difficiles à compresser. Les paramètres par défaut ont donc été modifiés pour réduire ce problème. Par défaut, la diffusion est maintenant désactivée et la dilatation a été définie sur 32 pixels (qui doivent correspondre aux résolutions 4K). Nous vous recommandons de basculer le projet existant vers ces nouveaux paramètres et de procéder à une réorganisation pour tirer parti de cette amélioration.

Le bouton « baking current Jeu de textures » a donc été supprimé. Pour faciliter la sélection des éléments à baker, plusieurs options ont été ajoutées dans les menus déroulants :

La fonctionnalité qui permettait auparavant de créer et de passer à différentes instances de shader a maintenant été déplacée dans les paramètres du Jeu de textures.
